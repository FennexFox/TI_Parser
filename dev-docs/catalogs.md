# Catalogs and verification

## Runtime boundary

Packaged `data/` catalogs are the calculation source of truth. Required missing,
corrupt, empty, incompatible, or unresolved data must produce an error or an
explicit incomplete result. Valid empty source lists, non-applying orgs,
zero-weight/locked research slots, and optional empty ship slots remain valid.
Unsupported scenarios never borrow another scenario's values.

`catalog_manifest.json` records catalog file SHA-256, schema versions, payload
fingerprints, and the bundle fingerprint. Runtime envelopes contain deterministic
source hashes, canonical scenarios, base rows, and exact overlays; timestamps and
mtimes are excluded. Module/location catalogs also have embedded canonical payload
fingerprints; loaders reject altered payloads and duplicate module IDs.

Normal commands reuse validated bundles within an invocation/session and validate
again for a new lifetime. They do not read raw game templates or DLLs.
`tests/test_runtime_raw_loader_guard.py` protects this boundary. Legacy
`load_trait_templates -> load_named_templates` and
`scenario_template_sources -> load_named_templates` utility edges remain isolated
for generator/raw-reference compatibility; they are not normal command paths.

## Generation

Run from the source checkout with explicit authoritative game inputs as needed:

```powershell
python tools/build_runtime_catalogs.py --templates-dir "C:\path\StreamingAssets\Templates"
python tools/build_module_catalog.py --help
python tools/build_location_catalog.py --help
python tools/build_research_catalog.py --help
```

`catalog_utils.py` owns shared generator helpers. Generated bytes use canonical
LF output; change generators and regenerate their outputs instead of repairing
catalogs by hand.

- Module generation writes `data/module_catalog.json` and
  [the module reference](reference/module_catalog.md). Template values still need
  save-specific mining, crew support, power, adviser, and faction effects.
- Location generation reads body, navigable, and orbit templates. Lagrange points
  are navigables rather than physical bodies. Variable solar output requires exact
  location evidence and never falls back to nominal power.
- Research v2 writes `data/research_catalog.json` and
  [the research reference](reference/research_catalog.md). Canonical `all`/`any`
  requirements retain gates; derived graph edges describe research prerequisites
  only. Completion/objectives/faction/nation state remains save-specific.
- Ship families resolve against the exact scenario tree and store recursive minimal
  deltas. Weapon names are collision-checked across families/scenarios. No DLC
  override means reuse of base rows, with no override claimed.

## Verification and releases

```powershell
python -m pytest -q
python tools/ti_save_parser.py --templates-dir "C:\path\StreamingAssets\Templates" catalog-verify --scenario ModernScenario
python tools/verify_fresh_export.py
python tools/build_beta_distribution.py --ref HEAD
python tools/verify_beta_distribution.py dist/TI_Parser-0.1.0b1.zip
```

Start with relevant test modules; run the full suite for cross-cutting runtime,
catalog, projection, or public CLI changes. Real-save tests require their explicit
fixture/environment configuration and are observational unless the save pair was
advanced under controlled conditions.

`catalog-verify` alone consumes raw templates as a CLI verification command.
It rebuilds normalized references, checks source hashes/overlays, and optionally
compares save-based solar, CP, MC, research, org, and ship calculations
(`rel_tol=1e-9`, `abs_tol=1e-6`). Exit 0 requires every check to pass;
failed/unavailable checks preserve `failed`/`partial` JSON and exit 2. Without a
local save, catalog checks run and save-dependent checks are unavailable; an
explicit missing save is an error.

`verify_fresh_export.py` checks committed bytes via a temporary
`git -c core.autocrlf=false archive HEAD`, then runs full/package-only suites and
supported scenario loads. It cannot validate uncommitted edits. The ZIP builder
also reads a committed ref and explicitly allowlists runtime files; tests,
developer docs/tools, raw DLLs/templates, and private saves are excluded.

Local passes do not establish remote matrix or ChatGPT acceptance, or permission
to redistribute game-derived data. See [outstanding acceptance](development-notes.md)
and the [data notice](../docs/BETA_DATA_NOTICE.md).
